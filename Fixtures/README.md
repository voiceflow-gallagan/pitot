# Fixtures

Golden-test inputs for `Core`. Expected outputs for edit operations live in `expected/`, named `<fixture>.<n>.json`. They are generated by `Tools/oracle` (`jsonc-parser` 3.3.1) from `Tools/oracle/ops.json`. Run `node run.js --check` there to confirm they are current.

An operation in `ops.json` has an `op` of `set`, `remove` or `insert`. A number in its `path` is an array index, as in `jsonc-parser`. `insert` adds an element at that index, and index `-1` appends. A path that goes on after an index edits inside that element. The Swift test maps these to `appendElement`, `insertElement`, `replaceElement`, `removeElement` and `editElement`.

## Where the Swift editor differs from the oracle

The Swift golden test compares every operation in `ops.json` byte for byte. For thirteen operations it compares against a hand-written file in `expected-swift/` instead of `expected/`. Those operations carry a `swiftExpected` field in `ops.json`. `node run.js --check` skips them but still requires the hand-written file to exist. The oracle output stays in `expected/` for reference.

| Operation | Oracle output | Swift output | Why |
|---|---|---|---|
| `single-line.2`, `integer-like-keys.3` (add a key to a minified object) | Reformats the whole file as indented JSON | Inserts `,"key":value` and leaves every other byte alone | A key edit must not rewrite the rest of the file |
| `single-line.3`, `integer-like-keys.4` (remove a key from a minified object) | Reformats the whole file | Removes the member and its comma only | Same reason |
| `tabs.3`, `settings-synthetic.9`, `keybindings.10` (remove the only key of an object) | Leaves an empty multi-line object, such as `{` newline `}` | Writes `{}` | Agreed rule: removing the only key yields `{}` |
| `array-single-line.2` to `.5` (add or remove an element in a single-line file) | Reformats the whole file as indented JSON | Adds or removes the element and its comma only | An element edit must not rewrite the rest of the file |
| `nested-arrays.3`, `array-numbers.5` (add or remove an element of a single-line array in a multi-line file) | Breaks that array into one element per line | Keeps the array on one line with its `, ` spacing | Agreed rule: single-line arrays stay single-line |

To add a deviation, add `"swiftExpected": "Fixtures/expected-swift/<name>.json"` to the operation and write that file by hand. Do not generate it with the Swift code it tests.

## Synthetic settings file

`settings-synthetic.json` is not derived from anyone's settings. Every name and value in it is made up. It has the shape of a well-used `settings.json`, so the editor is tested on a file of realistic size:

- 23 top-level keys in the order Claude Code appends them, not in alphabetical order. `model` is the last key.
- 2-space indent, LF line endings, a trailing newline and no comments.
- An `env` block of `EXAMPLE_VAR_n` names, and permission lists of about 280 `allow`, 40 `deny` and 30 `ask` rules.
- Hooks for twelve events. Some commands are about 1.5 KB long, and some contain `\"` and `\\` escapes.
- Plugins named like `plugin-a@example-marketplace`. Marketplace sources point to `https://example.com/` or to a relative folder.
- An empty array, an empty object, and an object whose only key is removed by operation 9.

Never paste real settings into this folder. Names of real people, companies, machines, home paths, plugins or marketplaces do not belong here.
